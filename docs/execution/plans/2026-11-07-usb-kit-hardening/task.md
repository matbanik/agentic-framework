### Evidence-First & Sequencing Rules

- **Evidence-first completion:** a row is `[x]` only when its deliverable exists and the handoff carries its evidence.
- **Red first:** each coder row runs the red command in its Task cell into its `uk-red-*` receipt before it changes any code, and its validation starts with the `--red` check of that receipt. AC-6, AC-7 and AC-12 are guards that pass on their first run (A-13), and `--red` requires them to pass. A red guard stops its row, and the plan records the defect.
- **Human rows:** rows 0, 2a, 12, 13 and 14 are `[B]` human gates until the human asks for them or reports them done. Rows 3a and 7a check the D-1 and D-2 rulings that the human typed on 2026-11-08. A script that changes a machine runs only when the human asks (stop condition 3). Each row's validation command then decides `[x]`.
- **Decisions:** row 4 waits for row 3a's check of the typed D-1 ruling, and row 8a for row 7a's check of the typed D-2 ruling. No row assumes an option. The validation of rows 3a and 7a passes only on a typed A (or, on row 7a, on `not applicable`). A ruling other than A sends that row back to planning before any code for it is written (stop condition 11).
- **The review barrier:** the handoff (H1-6) comes before the review, and the H2 artifacts come after `approved`.
- **No self-review:** the implementer dispatches the H1-7 review and never authors its verdict.
- **`[B]` is evidence-gated:** it is allowed only for a reproduced external error, a missing dependency, credential or permission, or a human-decision gate, each with a `### B-<row-id>` block.
- **Valid stops:** the plan's stop conditions, DONE, the review cap, an unavailable reviewer, or a human decision. Compaction continues the pass.
