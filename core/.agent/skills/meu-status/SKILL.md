# MEU Status SSOT Skill

## Purpose

The MEU Status SSOT replaces manual status tracking in `meu-registry.md` and `BUILD_PLAN.md` with a data-driven YAML file (`.agent/context/meu-status.yaml`) and associated CLI tool.

**Key principle**: YAML is the SSOT; Markdown status tables are generated regions. Humans/agents edit `meu-status.yaml` (or run the CLI), **never** the tables inside AUTOGEN markers.

## Quick Reference

### Query Commands

```bash
# List all MEUs (with optional filters)
uv run python tools/meu_status.py list
uv run python tools/meu_status.py list --status pending
uv run python tools/meu_status.py list --status pending --unblocked
uv run python tools/meu_status.py list --band P2 --phase 8c

# Next unblocked MEUs
uv run python tools/meu_status.py next
uv run python tools/meu_status.py next --band P2.6 --limit 3

# Get single MEU detail
uv run python tools/meu_status.py get MEU-91

# Summary statistics
uv run python tools/meu_status.py stats
```

### Update Commands

```bash
# Update MEU status (auto-stamps updated date)
uv run python tools/meu_status.py update MEU-91 in_progress
uv run python tools/meu_status.py update MEU-91 approved --note "All tests pass"
uv run python tools/meu_status.py update MEU-91 closed --reason "ADR-002 — descoped"
```

### Render Commands

```bash
# Regenerate Markdown regions from YAML
uv run python tools/meu_status.py render

# CI gate: check if regions are up-to-date (exit non-zero if drifted)
uv run python tools/meu_status.py render --check
```

## Status Enum

| Value | Icon | Meaning |
|-------|------|---------|
| `pending` | ⬜ | Not started |
| `deferred` | ⏸ | Intentionally postponed |
| `in_progress` | 🔵 | Implementation in progress |
| `ready_for_review` | 🟡 | Awaiting Codex validation |
| `changes_required` | 🔴 | Codex found issues |
| `approved` | ✅ | Both agents satisfied |
| `closed` | 🚫 | Won't fix (requires `closed_reason`) |

## Schema

The YAML file is validated against `tools/meu_status/meu-status.schema.json` (JSON Schema 2020-12). Key constraints:

- `additionalProperties: false` everywhere (no stale fields)
- `row_key` must be unique (handles legacy duplicate MEU IDs via suffix)
- `status` must be one of the 7 enum values
- `closed_reason` is required when status is `closed`
- `phase` must reference an existing phase ID
- `updated` must be `YYYY-MM-DD` format

## AUTOGEN Marker Protocol

Generated regions use HTML comment markers:

```markdown
<!-- BEGIN AUTOGEN:meu-status:phase-tracker -->
... generated content (do not edit) ...
<!-- END AUTOGEN:meu-status:phase-tracker -->
```

**Three generated regions** (regenerated by `render` / verified by `render --check`):
1. `:phase-tracker` — Phase Status Tracker table (BUILD_PLAN.md)
2. `:summary` — MEU Summary counts (BUILD_PLAN.md)
3. `:registry` — Per-phase MEU tables **+ `> Source:` links + preserved narrative sections** (meu-registry.md)

> **Canonical generated view:** `meu-registry.md` (`:registry`). Optional Spec/build-plan
> surfaces (`:phase-tracker`, `:summary`) use the same SSOT — keep AUTOGEN markers in place
> (see `templates/BUILD_PLAN-STUB.md`). Do not hand-maintain parallel MEU tables outside the SSOT.

## Migration (one-time bootstrap — do NOT re-run)

`migrate` parses the Markdown into the YAML. It was a **one-time bootstrap**; the SSOT is
now the source of truth. Re-running `migrate` would rebuild from Markdown and discard status
updates / narrative captured since. The command therefore **refuses to overwrite a populated
SSOT** unless you pass `--force`. For ongoing changes use `update` + `render`, never `migrate`.

## When to Use This Skill

- **After completing an MEU**: `update <row_key> approved`
- **At session start**: `list --status pending --unblocked` or `next`
- **When planning**: `stats` to see overall progress
- **Before commit**: `render --check` to verify docs are in sync
